⚙️ How It Works

The fundamentals before you build

🗺️ Scene Graph

A campaign is a directed graph of scenes. Each scene has a type, some text, and either a single next pointer or branching choices. The engine walks from scene to scene until it hits an ending scene.

  • Drop a .json in data/campaigns/ — no restart needed
  • Bot re-scans on every /campaign start
  • Browse available campaigns with /campaign list
  • Party assembles publicly, then plays in a private channel
  • Story scenes show a live vote display — majority wins
  • Combat uses the exact same engine as group adventures

💾 Persistent State

Everything carries forward for the full run. Decisions early in the campaign have real consequences at the boss.

  • HP damage from fights carries into the next scene
  • Ability cooldowns persist across all combat scenes
  • Party buffs (War Cry etc.) carry round-to-round
  • Items found stack their bonuses for the rest of the run
  • XP bonuses from items multiply the final reward
Vote timeout

Story choices have 90 seconds. If time runs out, the leading choice wins — or the first choice if nobody voted.

📋 The Outer Envelope

Every campaign file starts with this header
{ "id": "my_campaign", "title": "My Campaign Title", "emoji": "⚔️", "description": "One or two sentences shown in /campaign list.", "lore": "The longer flavour text shown when the party assembles. Use \\n\\n for paragraph breaks.", "min_party": 2, "max_party": 6, "join_window": 90, "color": 8356863, "start_scene": "first_scene_id", "scenes": { ... } }
  • id — unique, snake_case. Defaults to filename stem if omitted.
  • title — shown in menus and the private channel name.
  • emoji — single emoji shown in the campaign picker.
  • description — short blurb, ≤90 chars for best display in the dropdown.
  • lore — shown in the party assembly embed. Can be long.
  • min_party — minimum party size (default: 2). Start Now button enforces this.
  • max_party — maximum party size (default: 6).
  • join_window — seconds the join post stays open (default: 90).
  • color — decimal embed color. Convert hex: 0x7B2FBE → 8069054.
  • start_scene — the id of the first scene to run.

🎬 Scene Types

All scenes live in the "scenes" object, keyed by their ID

📖 story Narration & Choices

The workhorse. Shows text and optionally presents up to 4 buttons the party votes on. If you omit choices, use "next" and the scene advances automatically after 4 seconds.

With choices (party vote)

"my_scene": { "type": "story", "title": "The Cracked Gate", "text": "The ruins loom...", "choices": [ { "id": "scene_a", "label": "Take the main corridor", "emoji": "🚪", "hint": "Straightforward but exposed" }, { "id": "scene_b", "label": "Slip through the gap", "emoji": "🕯️", "hint": "That torch is a clue" } ] }

Auto-advance (no vote)

"cutscene": { "type": "story", "title": "A Beat of Silence", "text": "The door closes.", "next": "next_scene_id" }
Choice fields
  • id — scene to go to if this wins. Required.
  • label — button text, ~40 chars max. Required.
  • emoji — button emoji. Optional.
  • hint — italic sub-text in the embed. Telegraph tone, not outcome.

🎁 item Treasure Rooms

Shows a found item with flavour text and immediately applies its mechanical bonuses to every party member. Always has exactly one "next" — no branching.

"treasure_room": { "type": "item", "title": "The Scholar's Satchel", "text": "Inside: a vial of antitoxin...", "item": { "name": "Scholar's Satchel", "emoji": "🎒", "description": "Grants +10% max HP for this run.", "rarity": "uncommon", "party_hp_bonus": 10 }, "next": "next_scene_id" }

Item bonus fields

  • party_hp_bonus — % max HP increase for the whole campaign. Also heals each member for the amount gained. Only works in item scenes — ignored on combat loot.
  • first_round_bonus — % damage boost on round 1 of the boss fight only. Stacks across items.
  • xp_bonus_percent — multiplies final XP by (1 + value/100). Stacks additively.

Rarity → embed color

  • common → grey · uncommon → green · rare → blue
  • epic → purple · legendary → gold
  • Items with no bonus fields are still shown in the ending summary.

⚔️ combat Monster Fights

Runs the full group combat engine. HP, cooldowns, and party buffs carry into the next scene. Both on_win and on_lose are required.

"encounter": { "type": "combat", "title": "Animated Sentinels", "text": "The hall shakes...", "monster": { "name": "Stone Sentinel", "emoji": "🗿", "hp": 90, "attack": 14, "speed": 5, "armor": 3 }, "max_rounds": 8, "loot": { "name": "Sentinel Core", "emoji": "💎", "description": "A curiosity.", "rarity": "rare" }, "on_win": "hall_vault", "on_lose": "party_retreat" }

Monster fields

  • hp — base HP (1-person). Auto-scales: each extra member adds 70%. A 4-person party fights hp × 3.1.
  • attack — base attack power (same formula as group adventures).
  • speed — dodge/hit chance. Higher = harder to hit.
  • armor — flat damage reduction per hit.
  • max_rounds — monster "retreats" at this round (counts as a win).
  • loot — optional item shown after winning. Display-only — HP bonuses on loot are silently ignored.

Difficulty guidelines

  • Light — HP 60–80 · Attack 10–13 · Speed 5–8 · Armor 0–2 · Max 6–7
  • Standard — HP 80–120 · Attack 13–18 · Speed 6–10 · Armor 2–4 · Max 8–9
  • Heavy — HP 120–180 · Attack 18–22 · Speed 8–12 · Armor 3–6 · Max 10–12

💀 boss Final Battle

The climactic fight. Scaling HP, multiple attack phases, and an enrage timer. Uses the same engine as raid bosses. Both on_win and on_lose are required.

"final_fight": { "type": "boss", "title": "The Ruinlord Awakened", "text": "The ritual circle blazes...", "boss": { "name": "Ruinlord Vex", "emoji": "💀", "description": "An ancient sorcerer...", "hp": 500, "hp_per_fighter": 80, "attack": 22, "speed": 9, "color": 4980762, "enrage_round": 12, "phases": [ { "threshold": 0.65, "name": "Unbound", "emoji": "⚡", "msg": "The seals tear free!", "attack_mult": 1.25 }, { "threshold": 0.30, "name": "Ascendant", "emoji": "💢", "msg": "Vex dissolves into energy!", "attack_mult": 1.6 } ] }, "on_win": "victory", "on_lose": "defeat" }

Boss fields

  • hp — base HP at minimum party size (2 players).
  • hp_per_fighter — added per member beyond the first. 4-person: hp + hp_per_fighter × 3.
  • attack — base attack power.
  • speed — affects dodge/hit.
  • color — decimal embed color. Make it distinct from campaign color.
  • enrage_round — attacks become overwhelming from this round onward.
  • phases — array ordered highest threshold first. Omit or set [] for flat stats.

Phase fields

  • threshold — triggers when boss_hp / boss_max_hp drops below this.
  • name — phase name in the round header.
  • msg — narration in the phase shift announcement.
  • attack_mult — multiplies base attack. 1.3 = 30% stronger.

Difficulty guidelines

  • Short — Base HP 300–400 · HP/Fighter 50–70 · Attack 18–22 · Enrage 10–12
  • Medium — Base HP 450–600 · HP/Fighter 70–90 · Attack 22–26 · Enrage 12–14
  • Long — Base HP 600–800 · HP/Fighter 85–110 · Attack 25–30 · Enrage 14–16

⛺ checkpoint Rest Room

A safe zone between scenes. When the party reaches a checkpoint the engine fully heals every member to their max HP, then waits — with no time limit — until every player clicks ✅ Ready. The embed updates live as each person checks in. Once the last player is ready the campaign continues automatically.

"vault_rest": { "type": "checkpoint", "title": "The Vault Antechamber", "text": "A heavy door seals behind you. Dust hangs in the still air. Someone left iron rations in an alcove long ago. Rest here before the final push.", "next": "boss_antechamber" }

Fields

  • type — "checkpoint". Required.
  • title — shown as the embed title (prefixed with ⛺).
  • text — flavour narration for the rest room.
  • next — scene to continue to once all players are ready. Required.
What it does automatically
  • Heals every party member to full max HP before showing the embed.
  • Shows a live ready-check list — ⏳ becomes ✅ as each player clicks.
  • No timeout — the campaign pauses indefinitely until everyone is ready.
  • Advances to next the moment the last player clicks Ready.

🏁 ending Terminal Scene

Ends the campaign. outcome controls embed color and emoji — gold for win, dark for lose. The ending embed automatically lists all items found during the run.

Win

"victory": { "type": "ending", "outcome": "win", "title": "The Ruins Fall Silent", "text": "The Ruinlord dissolves...", "xp_reward": 250 }

Lose

"defeat": { "type": "ending", "outcome": "lose", "title": "Consumed by the Dark", "text": "The Ruinlord stands over you..." }
xp_reward — don't skip this

The boss scene reads xp_reward from your win ending to calculate rewards. If it's missing, the boss awards 0 XP to everyone. Always set it on your win ending. Suggested values: Short (2–3 fights) 120–180 · Medium (3–5) 200–280 · Long (5+) 300–400.

✨ XP: How It's Calculated

The boss scene handles this automatically from your win ending

The Formula

  1. Finds the "win" ending and reads its xp_reward.
  2. Each member's share scales by damage dealt:
    base × (0.6 + 0.4 × damage_share)
  3. KO'd players receive 40% of their calculated share.
  4. The whole pool is multiplied by any xp_bonus_percent accumulated from items.

Scaling Reference

Monster HP: hp × (1 + 0.70 × (party_size − 1)) Boss HP: hp + hp_per_fighter × (party_size − 1) Phase trigger: boss_hp / boss_max_hp < threshold → phases ordered highest first XP per player: base × (0.6 + 0.4 × dmg_share) × (1 + xp_bonus_pct / 100) KO'd players receive 40%

🗺️ Structuring Your Campaign

Practical patterns for building the scene graph

Minimum viable campaign

start (story) → fight (combat) → boss_intro (story) → boss (boss) → victory (ending) ↘ defeat (ending)

Recommended long campaign structure

┌─ path_a (story) ─┐ start (story) ──────┤ ├─ mid_fight (combat) ─ treasure (item) ─┐ └─ path_b (story) ─┘ │ ▼ ┌─ choice_x ─ fight_x (combat) ─────────────────────────────┤ convergence ────────┤ │ (story) └─ choice_y (story) ────────────────────────────────────── │ ▼ boss_intro (story) │ boss (boss) │ │ win ● ● lose

✅ Do This

  • Converge paths before the boss. Merge branches at a central scene, then one boss. Two separate bosses doubles your writing work.
  • Put item scenes after hard fights. Natural reward cadence — the HP bonus helps with what's coming.
  • Give every path something. If path A has a treasure room, give path B intel, a shortcut, or a cosmetic item. Players notice.
  • Have at least 2 lose endings. One for early failures, one for the boss — different text for each.
  • Write lose endings that gesture forward. The best ones acknowledge what comes next rather than dead-ending narratively.

❌ Avoid This

  • Missing scene IDs. If on_win, on_lose, next, or a choice id references a scene that doesn't exist, the engine sends an error embed and ends the campaign immediately.
  • Forgetting on_lose. Required on every combat scene. A party wipe with no on_lose crashes the engine.
  • HP bonuses on combat loot. Combat loot is display-only — party_hp_bonus is silently ignored. Use a dedicated item scene instead.
  • Missing xp_reward. If the win ending has no xp_reward, the boss awards 0 XP to everyone.
  • Phases in wrong order. Must be highest threshold first — 0.65 before 0.30.
  • More than 4 choices. The 5th button slot is used internally — a 5th choice is silently ignored.

✅ Validation

Run this before dropping the file in — broken scene IDs end campaigns silently

Checklist

  • Valid JSON — paste into jsonlint.com or use the Python validator
  • start_scene exists in "scenes"
  • Every on_win, on_lose, next, and choice id points to a real scene
  • Every combat scene has both on_win and on_lose
  • Every item scene has "next"
  • Every checkpoint scene has "next"
  • Every story scene has either "choices" or "next"
  • At least one ending with "outcome": "win" exists
  • Win ending has "xp_reward" set to a non-zero value
  • Boss phases are ordered highest threshold first
  • id doesn't collide with an existing campaign file

Quick Python Validator

import json data = json.load(open("my_campaign.json")) scenes = data["scenes"] all_ids = set(scenes.keys()) errors = [] for sid, scene in scenes.items(): for field in ["next", "on_win", "on_lose"]: target = scene.get(field) if target and target not in all_ids: errors.append( f"{sid}.{field} → '{target}' not found") for choice in scene.get("choices", []): if choice["id"] not in all_ids: errors.append( f"{sid} choice '{choice['label']}'" f" → '{choice['id']}' not found") if scene.get("type") == "checkpoint" and not scene.get("next"): errors.append(f"{sid}: checkpoint is missing 'next'") if errors: for e in errors: print("ERROR:", e) else: from collections import Counter types = Counter(s["type"] for s in scenes.values()) print("OK —", dict(types)) wins = [s for s, v in scenes.items() if v.get("outcome") == "win"] print("Win endings:", wins)

📌 Quick Reference

Everything on one card

Scene types

  • story — text + choices (vote) or auto-next via next
  • item — text + item object + next
  • combat — monster fight → on_win / on_lose
  • boss — phased boss fight → on_win / on_lose
  • checkpoint — heals party + waits for everyone to ready up → next
  • ending — terminal (outcome: "win" or "lose")

Item bonuses (item scenes only)

  • party_hp_bonus — % max HP for full campaign
  • first_round_bonus — % damage on boss round 1 only
  • xp_bonus_percent — % multiplier on final XP

Player commands

  • /campaign list — browse available campaigns
  • /campaign start — launch a party campaign
  • /campaign cancel — cancel the current campaign
