MAYFLOWER STUDIOS — PAID WORLDS / STRIPE
==========================================

THE IMPORTANT PART
------------------
You do NOT configure Stripe for every world.

Run RUN-ME-ONCE-STRIPE.bat one time on your Windows computer.
It connects Stripe to the website, deploys the small payment backend, publishes the security rules, and creates the Stripe webhook.

After setup, every paid world is simply:

  Admin -> 3DX World Library -> + New world
  1. Upload the .world file
  2. Add screenshots
  3. Add name + description
  4. Choose Paid world
  5. Type the price, e.g. 4.99
  6. Publish

That is all you do per world.

WHAT THE SITE DOES AUTOMATICALLY
--------------------------------
• Encrypts a paid .world file in your browser before uploading it.
• Keeps the AES decryption key in the private worldPrivate database node.
• Reads the price from Firebase server-side.
• Creates Stripe Checkout when a buyer clicks Buy.
• Requires the buyer to be signed into a Mayflower account.
• Verifies payment from Stripe's signed webhook.
• Attaches the purchase to that Mayflower account.
• Shows purchased worlds when the buyer comes back later.
• Releases the decryption key only after account ownership is verified.
• Decrypts the .world file locally in the buyer's browser for download.
• Revokes access after a full Stripe refund or lost dispute.
• Never stores card numbers on Mayflower Studios.

WHY THIS VERSION IS SIMPLER
---------------------------
It does NOT deploy a Cloud Storage event trigger and does NOT use Cloud Storage signed URLs.
That means there is no Eventarc/Pub/Sub service-agent role setup and no Service Account Token Creator step.
Only three HTTPS Functions are deployed: checkout, Stripe webhook, and purchased-world unlock.

RESUMING FROM AN EARLIER ATTEMPT
--------------------------------
If you already entered the Stripe key/webhook setup, run:
  RESUME-STRIPE-SETUP.bat

The resume script republishes the new encrypted-world Database/Storage rules and deploys only the three HTTPS Functions.

If you uploaded a PAID world using an older build, edit it and select its .world file again once. That converts it to the encrypted format.

SECURITY
--------
Never put sk_test_, sk_live_, or whsec_ secrets in HTML, JavaScript, Firebase Realtime Database, or GitHub. The setup stores them in Firebase Secret Manager.

As with any downloadable product, a legitimate purchaser can choose to redistribute the file after downloading it. The encryption prevents unpaid direct access; it is not DRM against someone who already owns the decrypted file.
